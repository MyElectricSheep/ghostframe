An experiment in embedding-based steganography

A secret message, hidden in plain pixels.

An AI image model turns every part of a photo into a vector embedding, a list of numbers describing what it sees. Ghostframe nudges the pixels, by at most 2 or 8 levels out of 255, until those numbers spell out a short encrypted message. The same frozen model reads it back. The message is private and tamper-evident.

What the angle means

The model describes each tile with 512 numbers, its embedding. Think of those numbers as an arrow: tiles that look alike to the model point in similar directions. The angle is how differently the model now describes the same tile. 0° would mean no change; 90° would mean an unrelated description.

How it works

A frozen, public image model, SqueezeNet 1.1, looks at the photo one tile at a time. For each tile it produces an embedding: the list of numbers the model uses to describe that tile. The encoder nudges pixels until those numbers spell out the encrypted message. The model’s weights never change. Only the pixels do.

  1. {{ f.n }}
  2. Technical detail
    • Model: SqueezeNet 1.1 (original paper), pinned checkpoint (sha256 b8a52dc0…) and a pinned calibration file. PyTorch 2.7.1 CPU.
    • Encryption: . The key is derived from the passphrase with , which makes guessing deliberately slow.
    • Tamper evidence: if the hidden message is altered, authentication fails and the reader returns “No message found.” instead of a wrong message.
    • The encoder is a standard optimiser. The model only reads; it never writes anything.
    • Related work. Ghostframe builds on an established idea: hide data by optimising an image so a frozen network reads it out. See Vukotić et al. (WIFS 2018) and Fernandez et al. (ICASSP 2022), whose fixed “carrier” directions in a pretrained feature space are close to ours. Kishore et al. (ICLR 2022) apply the same principle to steganography (FNNS), and Luo et al. (ACM MM 2023) add a key. What’s ours is the engineering and the testing, not the method. Also:FNNS codeFNNS variants (US patent 12,033,233)Cs-FNNS follow-up
    • Encoding and decoding run on a server. Browser decoding hasn’t been validated.
